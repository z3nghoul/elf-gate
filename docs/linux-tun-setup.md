# Режим TUN на Linux: установка

Для TUN Xray должен создавать сетевой интерфейс и менять маршруты. Это требует `CAP_NET_ADMIN`.
**elf-gate сам никогда не вызывает `sudo`**: команды ниже выполняете вы.

## Основной путь: копия Xray с `cap_net_admin`

Нужна копия `xray`, принадлежащая root и недоступная вам на запись. Копию в домашней папке использовать
нельзя: любой процесс пользователя мог бы подменить файл, который запускается с повышенными правами.

```bash
sudo install -d -m 0755 -o root -g root /usr/local/lib/elf-gate
sudo install -m 0755 -o root -g root /путь/к/xray /usr/local/lib/elf-gate/xray
sudo install -m 0644 -o root -g root /путь/к/geoip.dat /путь/к/geosite.dat /usr/local/lib/elf-gate/
sudo setcap cap_net_admin+ep /usr/local/lib/elf-gate/xray
```

Те же команды elf-gate показывает в окне, если копии нет или она небезопасна. Путь можно изменить в
`config.toml`: `[tun] xray_path = "..."`. elf-gate проверяет, что файл и все его родительские папки принадлежат
root и не доступны на запись группе и всем; иначе TUN не запускается.

После установки TUN включается клавишей `t`, затем `Enter` на сервере.

**Обновление Xray**: повторите три команды `install` и `setcap` (после замены файла capability пропадает).

## Запасной путь: `sudo elf-gate`

```bash
sudo elf-gate
```

Конфиг и состояние остаются в домашней папке пользователя, запустившего `sudo` (по `SUDO_USER`), файлы,
созданные от root, возвращаются пользователю. Ядро для TUN всё равно должно быть из «доверенного» места
(root-owned), см. выше.

## Как elf-gate убирает за собой

- Xray создаёт интерфейс `elfgate0` и маршруты и сам убирает их при выходе. После `kill -9` они исчезают с
  закрытием устройства.
- Ядро с file capabilities не получает сигнал при смерти родителя (ядро Linux сбрасывает `PDEATHSIG` при запуске
  такого файла). Поэтому elf-gate запускает его через маленький сторож (`elf-gate --supervise ...`), который
  останавливает ядро, когда elf-gate умирает. Это проверено тестом (docs/tun-research/lab, сценарий 07).
- В `state.json` записывается запущенный TUN. Если процесс убит так, что даже сторож не отработал, при следующем
  запуске elf-gate находит и останавливает остаток.

## Проверка окружения перед стартом

| Что | Если не так |
|---|---|
| `/dev/net/tun` есть | подсказка `sudo modprobe tun` |
| Копия Xray найдена, принадлежит root, недоступна на запись | окно с командами установки |
| У ядра есть `cap_net_admin` (или elf-gate под root) | окно с командой `setcap`; тот же текст, если ядро само сообщит `operation not permitted` |
| `rp_filter` на интерфейсе с маршрутом по умолчанию не строгий (1) | предупреждение с командой `sysctl`; **elf-gate настройки не меняет** |

Строгий `rp_filter` (значение 1) ломает «прямой» трафик через TUN: ответы отбрасываются.
Проверить: `sysctl net.ipv4.conf.all.rp_filter net.ipv4.conf.<интерфейс>.rp_filter` (действует большее значение).

## DNS

Системный DNS не изменяется. Домены из правил «через VPN» (пресет discord-only и ваши правила) резолвятся
через туннель средствами DNS-модуля Xray, остальные как раньше. Вышестоящие резолверы берутся из
`/run/systemd/resolve/resolv.conf` (или `/etc/resolv.conf`), заглушки `127.x` пропускаются. Можно задать вручную:
`[tun] local_dns = ["192.168.1.1"]`, `tunnel_dns = "1.1.1.1"`.
