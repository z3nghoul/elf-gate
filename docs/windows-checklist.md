# Windows: ручная проверка

Пункты, которые нельзя проверить на Linux. Отмечать `[x]` после проверки на Windows 10/11 x64.

## Этап 1. Каркас TUI

- [ ] `elf-gate.exe` запускается в Windows Terminal и в классической консоли (conhost), TUI рисуется без артефактов.
- [ ] Кириллица и символы `●`, `▶`, `▼` отображаются корректно.
- [ ] Каждое нажатие клавиши обрабатывается один раз (на Windows crossterm присылает события Press и Release, Release отфильтрован).
- [ ] Изменение размера окна не ломает раскладку; при размере меньше 80x24 появляется сообщение.
- [ ] Debug-сборка: `F12` вызывает панику, консоль возвращается в нормальный режим (курсор виден, эхо включено).
- [ ] Лог пишется в файл (`%APPDATA%\elf-gate\logs`) и ротируется по дням.

## Этап 2. Модель, парсер, конфиг

- [ ] `config.toml` создаётся в `%APPDATA%\elf-gate\` после добавления сервера через `a`.
- [ ] Ссылка с кириллицей и эмодзи вставляется из буфера обмена консоли (Ctrl+V / правый клик) и имя отображается корректно.
- [ ] После перезапуска добавленные сервера на месте.

## Этап 3. Управление ядром

- [ ] Запуск ядра не открывает окно консоли (`CREATE_NO_WINDOW`).
- [ ] После закрытия окна терминала крестиком в диспетчере задач нет `xray.exe` (Job Object, `KILL_ON_JOB_CLOSE`).
- [ ] Убийство `elf-gate.exe` в диспетчере задач убивает `xray.exe`.
- [ ] `d` и смена сервера останавливают `xray.exe` (на Windows остановка без grace-периода, `TerminateProcess`).
- [ ] `cargo test xray::integration_tests` проходит с `bin\xray.exe` (путь через `XRAY_PATH`).
- [ ] Реальный сервер: `curl.exe -x socks5h://127.0.0.1:10808 https://ifconfig.me` показывает IP сервера.

## Этап 4. Системный прокси

- [ ] После подключения `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` содержит
  `ProxyEnable=1`, `ProxyServer=127.0.0.1:10809`, `ProxyOverride` из `[proxy].bypass`.
- [ ] Edge и Chrome без своих настроек прокси ходят через сервер (`https://ifconfig.me` показывает IP сервера),
  изменение подхватывается сразу, без перезапуска браузера (`InternetSetOptionW`).
- [ ] Если до запуска был свой прокси (в «Параметры -> Сеть -> Прокси»), после `d` и после выхода он такой же,
  как был, включая случай, когда `ProxyOverride` не существовал (значение удаляется).
- [ ] Убить `elf-gate.exe` в диспетчере задач, затем запустить снова: прокси вернулся к исходному
  состоянию, в логе строка «восстановлены прежние настройки системного прокси».
- [ ] Закрыть окно консоли крестиком, выйти из сеанса, выключить ПК (`CTRL_CLOSE/LOGOFF/SHUTDOWN_EVENT`):
  системный прокси восстановлен.
- [ ] Искусственная паника (debug, `F12`) при активном подключении: прокси восстановлен.
- [ ] `cargo test` на Windows проходит (тесты контроллера на моке; тесты с Xray пропускаются).

## Этап 5. Режим TUN и правила по процессам

**Для того, кто проверяет, без опыта.** Сборка: `elf-gate-windows-test.zip` из CI (папка с `elf-gate.exe`, `xray.exe`,
`wintun.dll`, `geoip.dat`, `geosite.dat`). Понадобятся: Windows 10 или 11, учётная запись с правом администратора,
Discord (клиент и аккаунт) и ссылка на сервер, которую вам передадут отдельно.

### Подготовка (один раз)
1. Распакуйте архив в простую папку, например `C:\elf-gate-test`. Все файлы должны лежать в одной папке.
2. Если SmartScreen пишет «Система Windows защитила ваш компьютер»: «Подробнее», «Выполнить в любом случае».
3. Откройте Windows Terminal в этой папке (Windows 11: правый клик по пустому месту, «Открыть в Терминале»;
   Windows 10: в адресной строке Проводника напишите `wt`). Запустите `.\elf-gate.exe`.
4. Нажмите `a`, вставьте ссылку на сервер (Ctrl+Shift+V), Enter.

### Проверки
Формат: **сделайте** и **напишите, что увидели** (если не получилось, напишите, что именно). Скриншоты приветствуются,
только без ссылки на сервер.

| № | Сделайте | Что написать |
|---|---|---|
| 1 | Нажмите `t`. Посмотрите на строку состояния внизу. | Что там написано (должно быть `TUN`). |
| 2 | Выберите сервер стрелками, нажмите Enter. | Появилось ли окно Windows «Разрешить этому приложению вносить изменения» (UAC). Нажмите «Да». |
| 3 | После UAC откроется **новое** окно elf-gate (от имени администратора) и само подключится. | Подключилось ли, что внизу. Исходное окно закрылось? |
| 4 | Если появился вопрос про пресет «только Discord»: нажмите `y` (да). | Был ли вопрос, что выбрали. |
| 5 | Откройте в браузере https://2ip.ru | Какой IP и страна (при «только Discord» это должен быть **ваш обычный** IP). |
| 6 | Откройте Discord, зайдите в голосовой канал, поговорите минуту (лучше с кем-то). | Слышно ли вас и вы слышите ли, есть ли заикания, задержка. |
| 7 | Включите демонстрацию экрана в Discord на 1-2 минуты. | Работает ли, качество, есть ли разрывы. |
| 8 | Откройте Диспетчер задач (Ctrl+Shift+Esc), вкладка «Подробности». | Есть ли `xray.exe`, сколько процессов. Параметры > Сеть и Интернет: появился ли новый адаптер (с именем elf-gate). |
| 9 | В окне elf-gate нажмите `r` (правила). Нажмите `m` (режим), затем `Esc`. Нажмите `r` ещё раз. | Какой режим показан (`exclude` или `include`). Попросит ли перезапустить ядро, что нажали. |
| 10 | В режиме `exclude` (всё через VPN) откройте https://2ip.ru | IP и страна (должен быть IP **сервера**). Откройте страницу вашего роутера (например 192.168.0.1): открывается ли. |
| 11 | Нажмите `r`, `a`, выберите «Процесс: выбрать из запущенных», найдите свой браузер (например `chrome`). | Есть ли браузер в списке, как он называется в списке. |
| 12 | Нажмите `d` (отключиться). | Исчез ли адаптер из «Сеть и Интернет», пропал ли `xray.exe` из Диспетчера задач, работает ли интернет (2ip.ru показывает ваш обычный IP). |
| 13 | Снова подключитесь и **закройте окно терминала крестиком**. | Исчез ли адаптер и `xray.exe`, работает ли интернет без elf-gate. |
| 14 | Снова подключитесь, в Диспетчере задач **завершите** `elf-gate.exe` принудительно. | То же: адаптер, `xray.exe`, интернет. Запустите `elf-gate.exe` снова: есть ли в журнале запись про остаток прошлого запуска. |
| 15 | Нажмите `l` (журнал), если что-то работало не так. | Сфотографируйте экран журнала. |

### Что прислать
1. Заполненную таблицу (этот файл или текст).
2. Скриншоты окна elf-gate и, если есть, окна с ошибкой.
3. Версию сборки: `.\elf-gate.exe --version`; версию Windows (`winver`); антивирус.
4. Журнал из `%APPDATA%\elf-gate\logs\` (ссылок и паролей там нет).
**Не присылайте** `config.toml` и папку `run`: в них данные сервера.

### Для разработчика (что именно проверяют эти шаги)
- [ ] Windows: UAC и перезапуск `ShellExecuteW runas --tun`, автоподключение к последнему серверу (`[ui].last_server`).
- [ ] Адаптер Wintun создаётся, `wintun.dll` найден рядом с `xray.exe`, после выхода исчезает.
- [ ] `autoSystemWfpBlockLeak: ["misconfigtun"]` не ломает интернет и убирается при выходе, в том числе при завершении процесса.
- [ ] Правила `process` на Windows срабатывают (регистр имён: Windows-имена в пресете записаны как `Discord`, `steam` без `.exe`; если
  у вас `discord.exe` в нижнем регистре, нужен выбор через список запущенных программ).
- [ ] DNS по доменам через туннель работает с реальным системным резолвером; `GetAdaptersAddresses` возвращает физический адаптер.
- [ ] Job Object убивает `xray.exe` при закрытии окна и при завершении `elf-gate.exe`.

## Этап 6. Подписки, пинг, автоперебор fp, основной/запасной (сделайте - напишите, что увидели)

- [ ] `p`: сделайте пинг всех серверов в режиме `tcp`. Напишите значения и завис ли интерфейс.
- [ ] В `%APPDATA%\elf-gate\config.toml` поставьте `[ping] mode = "url"`, перезапустите, `p`. Напишите значения и
  мигают ли окна консоли (временные `xray.exe` запускаются без окна; Job Object убирает их при закрытии).
- [ ] Подписка (`a`, ссылка https): группа появилась, в деталях группы трафик и срок (`subscription-userinfo`),
  `u` обновляет. Проверяется `reqwest` с SChannel (системные сертификаты, TLS на Windows 10/11).
- [ ] Подписка без интернета: ошибка в строке статуса, старый список на месте.
- [ ] В режиме TUN (exclude) `u` и добавление подписки работают, пока туннель поднят (правило `process: elf-gate` ->
  direct). Напишите, открылась ли подписка в TUN и через какой IP (подписка, блокирующая IP VPS, должна открыться).
- [ ] Автоперебор fp: сервер, у которого `fp=chrome` блокируется провайдером. Напишите, подобран ли fp и какой.
- [ ] Основной/запасной (`b`): подключитесь к основному, остановите его на сервере, замерьте время до смены IP; верните
  основной и замерьте время возврата (ожидаем до ~10-15 с в обе стороны).
- [ ] `z` фрагментация ClientHello: подключение работает, скорость.
- [ ] Автозапуск (запись `Run` в реестре): пока включается только из кода (экран настроек появится на этапе 8); значение
  `elf-gate` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` создаётся и удаляется, кавычки вокруг пути с пробелами.

## Этап 7. Правила, пресеты (сделайте - напишите, что увидели)

- [ ] PROXY-режим, правило `domain` «напрямую» (например `2ip.ru`): откройте `https://2ip.ru` в Edge. Напишите, какой IP
  (должен быть ваш, а не сервера) и содержит ли «Параметры -> Прокси» в списке исключений `2ip.ru;*.2ip.ru`.
- [ ] Включите пресет `ua-direct` и откройте любой сайт в зоне `.ua`: напишите IP (ваш) и что написано в подсказке пресета.
- [ ] Включите пресет `block-quic`, откройте в Chrome сайт с HTTP/3 (например `https://cloudflare-quic.com`): напишите,
  сработал ли откат на TCP (в TUN-режиме).
- [ ] Для сервера с `flow=xtls-rprx-vision` в деталях видна строка `QUIC: UDP/443 закрыт самим Xray`.
- [ ] Имена процессов в пресетах на Windows: `Discord`, `steam` и т.д. (без `.exe`, регистр). Какие процессы нашлись в
  списке запущенных (`r`, `a`, «Процесс: выбрать из запущенных») и как они названы.

## Этап 7.5. Фоновая часть (сделайте - напишите, что увидели)

- [ ] `elf-gate.exe` сам запускает `elf-gated.exe` без окна консоли (`DETACHED_PROCESS | CREATE_NO_WINDOW`); закрытие
  интерфейса VPN не рвёт; один `elf-gated.exe` на пользователя (именованный канал `\\.\pipe\elf-gate-<user>`, первый экземпляр = замок).
- [ ] Канал недоступен другому пользователю (DACL `D:P(A;;GA;;;OW)`): проверьте с учётной записью другого пользователя.
- [ ] `Q` останавливает фон и убирает прокси/адаптер; принудительное завершение `elf-gated.exe` оставляет очистку следующему запуску.
- [ ] TUN: фон перезапускает себя через UAC с `--tun`, интерфейс переподключается; новый фон бинд канала сразу после выхода старого.
