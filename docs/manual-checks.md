# Ручные проверки

То, что нельзя автоматизировать без внешнего окружения. Отмечать `[x]` после проверки.

## Этап 3. Управление ядром

- [ ] Реальный сервер (VPS): подключиться к нему из TUI, затем
  `curl -x socks5h://127.0.0.1:10808 https://ifconfig.me` показывает IP сервера.
- [ ] Закрыть окно терминала крестиком или убить терминал: `pgrep -x xray` пусто.
- [ ] Смена сервера при активном подключении: ядро перезапускается с новым конфигом, старого процесса нет.
- [ ] `d` во время подключения (до готовности ядра) не оставляет процесс xray.
- [ ] Занятый порт (`nc -l 10808`) даёт сообщение «порт 10808 (socks) уже занят…», процесс не запускается.
- [ ] Неверный `xray_path` даёт сообщение про `xray_path`.

Автоматически уже проверено (Linux): `kill -9` приложения убивает дочерний `xray`
(`PR_SET_PDEATHSIG`), проход трафика по цепочке клиент -> локальный сервер -> HTTP,
остановка ядра, раннее падение ядра, занятый порт.

## Этап 4. Системный прокси

Автоматически проверено на Linux (KDE, `kwriteconfig6`, изолированный `XDG_CONFIG_HOME`; GNOME через
GSettings-бэкенд `keyfile`): включение, возврат прежних настроек пользователя, `kill -9` с
восстановлением при следующем запуске, SIGTERM, SIGHUP, panic hook, обычный выход.
Не проверено на живых программах, нужен реальный сеанс:

- [ ] [KDE] Подключиться к серверу из TUI. Chrome и Firefox («системные настройки прокси») ходят через сервер
  (`https://ifconfig.me` показывает IP сервера). После `d` и после выхода снова свой IP.
- [ ] [KDE] Если в «Параметры системы -> Сеть -> Прокси» уже был свой прокси, после выхода он такой же, как был.
- [ ] [KDE] Формат `socksProxy=socks://127.0.0.1:10808` и CIDR в `NoProxyFor` (`10.0.0.0/8`) понимаются
  KDE-программами. Если нет, поправить формат в `platform/linux/proxy.rs`.
- [ ] [GNOME] Те же пункты на живом сеансе GNOME (Chrome, Firefox, настройки сети GNOME показывают «Вручную»).
- [ ] [Linux, прочее окружение] В окружении без GNOME/KDE (например, XFCE, i3) прокси не трогается,
  в строке статуса подсказка с адресами `127.0.0.1:<порт>` и советом про TUN.
- [ ] `set_system_proxy = false` в `config.toml`: при подключении системные настройки не меняются.
- [ ] Закрыть окно терминала (SIGHUP) при активном подключении: прежние настройки вернулись.
