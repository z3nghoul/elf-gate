# Дополнения к плану (поверх SPEC.md)

SPEC.md не правится. Уточнения, принятые в ходе работы, записываются здесь и учитываются
при реализации соответствующего этапа.

## Этап 6. Подписки, пинг: проверка конфигов Xray

Сейчас `xray::validate::check` запускает `xray run -test` для каждого сервера при добавлении,
при старте приложения и перед подключением. Для подписок на сотни серверов это надо
оптимизировать:

- **Кеш вердиктов** `xray run -test` по ключу: хеш сгенерированного конфига + версия Xray
  (вывод `xray version`). Один и тот же конфиг на той же версии повторно не проверяется.
  Кеш хранится в `state.json` (или отдельным файлом рядом) и сбрасывается при смене версии Xray.
- **Фоновая проверка** с лимитом 4 параллельных процессов `xray run -test`
  (так же, как URL-пинг), интерфейс не блокируется.
- **Перепроверка только изменившихся серверов**: при обновлении подписки проверяются
  серверы, у которых изменился хеш конфига; остальные берут вердикт из кеша.
- Проверка перед подключением остаётся, но использует кеш (без запуска процесса, если ключ найден).

## Этап 4 (сделано)

- Прежние настройки прокси сохраняются в `state.json` до изменения и восстанавливаются из него
  при выходе, panic hook, SIGTERM/SIGHUP/консольных событиях и при следующем запуске после сбоя.
- Команды системного прокси выполняет один выделенный поток (порядок команд, UI не блокируется).
- Трейт: `current()` возвращает снимок настроек, `disable(previous)` восстанавливает его,
  `enable(addr, bypass)` принимает `ProxyAddr` (HTTP и SOCKS порты), а не одну строку.
- Известное ограничение: нет защиты от двух одновременно запущенных экземпляров.

## Этап 6. Автоматический перебор TLS fingerprint

Находка с живого сервера: у части российских провайдеров соединение с `fp=chrome` ломается
(в логе сервера Xray `REALITY: processed invalid connection ... failed to read client hello`;
вероятно, большой ClientHello с постквантовым ключом режется ТСПУ), а с `fp=firefox` тот же сервер работает.

Сейчас fp меняется вручную (клавиша `f`, переопределение в `[[overrides]]` в `config.toml`, подсказка
«попробуйте fp=firefox», когда ядро логирует серию ошибок). На этапе 6, вместе с пингом:

- Если сервер недоступен с текущим fp (URL-пинг не проходит, а TCP-пинг проходит), автоматически
  перебрать fp в порядке `firefox`, `chrome`, `safari`, `ios`, `edge`, `random`, `qq` и проверить каждый
  временным ядром (как URL-пинг, не более 4 параллельно).
- Первый сработавший fp предложить пользователю (или применить как переопределение с пометкой
  «подобран автоматически»); результат кешировать по серверу, перепроверять при смене версии Xray.
- Параметр `fp` из ссылки не подменять: подобранное значение живёт только в переопределении.

## Этап 1-4 (дополнения, сделано)

- Парсер `vless://` поддерживает `authority` и `mode=multi` для grpc (`grpcSettings.authority`, `multiMode`).
- Реальные тексты ошибок ядра при блокировке рукопожатия пока не известны: эвристика подсказки про fp
  (3 предупреждения или ошибки ядра за 30 с) настроена наугад и должна быть сверена с логом живого сервера.

## Уточнения пользователя (ноябрь 2026)

Целевая схема: максимум два сервера. Прямой (Финляндия) и запасной каскадный вход в РФ для режима
белых списков. Большие пулы серверов не приоритет.

### Этап 6. Автопереключение основной / запасной сервер

- Автопереключение делается под схему «основной + запасной», а не под большие пулы.
- Проверка доступности средствами Xray (`observatory` / `burstObservatory`), а не своим пингом.
- Возврат на основной сервер, когда он снова доступен (с гистерезисом, чтобы не дёргать соединение).
- Пользователь явно назначает роли (основной, запасной) в настройках сервера.
- Это относится к 4-му пункту плана этапа 6 про перебор fp: перебор остаётся, но не на сотнях серверов.

### Этапы 2 и 7. Фрагментация TLS ClientHello

- Опция на сервер, настраивается через настройки Xray (`fragment` в `sockopt.dialerProxy` или
  `freedom` с `fragment`, способ выбрать при реализации и проверить `xray run -test`).
- По умолчанию выключена. Переключается в деталях сервера рядом с fp, сохраняется как
  переопределение в `[[overrides]]` в `config.toml` (как fp).
- В `Server` появляется поле переопределения, генератор конфига добавляет настройку только при включении.

### Этап 7. Пресет «блокировать UDP 443 (QUIC)»

- Правило `network = udp`, `port = 443` с `outboundTag = block`, чтобы браузеры уходили с QUIC на TCP.
- Оформляется как встроенный пресет в `presets.toml`, **по умолчанию включён**.
- Важно для Discord: голос и стримы Discord идут по UDP на других портах, блокировка касается
  только 443. Проверить это в исследовании 5.1 и на живом сервере.

## Этап 5 (из исследования 5.1, см. docs/tun-research.md)

- Эвристика подсказки про `fp` опирается на предупреждения и ошибки ядра, но ошибки рукопожатия Xray пишет на уровне
  `[Info]` (`failed to find an available destination > common/retry: [EOF]`). При `loglevel=warning` подсказка молчит.
  Решение по `loglevel` или иному признаку принимается вместе с утверждением вывода 5.1.
- Домен VPS в режиме TUN резолвить самим до подъёма TUN и подставлять IP в аутбаунд (в лаборатории Xray 26.11.9 не смог
  резолвить домен VPS по сети при поднятом TUN).
