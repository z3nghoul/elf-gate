# Итоги по аудиту (продолжение docs/AUDIT.md)

Аудит: `docs/AUDIT.md` (коммит `9e08621`). Работа шла двумя прогонами; здесь итог по каждому пункту, отличия от
аудита и новые проблемы, найденные по ходу. Проверки каждого коммита: `cargo build --release`,
`cargo clippy --release --all-targets -- -D warnings` для Linux и для `x86_64-pc-windows-gnu`, `cargo test`
(333 юнит-теста и 3 e2e), затем проверка, что в `$TMPDIR` нет новых `elf-gate-*` и нет живых `xray`/`elf-gated`.
Windows-код проверялся только компиляцией и clippy, на настоящей Windows ничего не запускалось.

## Что сделано иначе, чем в аудите, и почему

- **S1.** Аудит предлагал `nix::unistd::fchownat` с `FchownatFlags::NoFollowSymlink`. В nix 0.31 флаги это
  `AtFlags::AT_SYMLINK_NOFOLLOW`, их и использовал. Кроме `fchownat` обход дерева сам пропускает симлинки
  (`symlink_metadata`), потому что путь в списке `chown` тоже не должен вести за пределы дерева. Менять владельца
  только у файлов, созданных процессом, не стал: это сильнее меняет поведение.
- **F1.** Аудит просил проверять права и файлы «до запуска». Права для TUN уже проверял `tun::preflight`
  (`core_can_create_tun`, на Windows это `is_elevated`), поэтому добавлена проверка там, где её не было, то есть перед
  `xray run -test`: нечитаемый бинарник не запускается, а нечитаемые или отсутствующие `geoip.dat`/`geosite.dat` вместе
  с упавшим запуском дают `Unavailable` с нашим текстом и не кешируются. Сбой без слов Xray о конфиге
  (`Failed to start` или `infra/conf`) тоже `Unavailable`. Коды Windows 2, 5, 1314 распознаются только после маркеров
  (`errno `, `error code `, `winerror `, `0x`): Go обычно печатает текст, а не число, поэтому это написано по образцу.
  Русские и украинские фразы написаны по памяти и ждут проверки на ru/uk Windows.
- **F2.** `debug_assert!` на «воркер tokio» невозможен: у потоков `spawn_blocking` то же имя. Закреплено тестами и
  записью в `docs/decisions.md`.
- **F11.** Версия и хэши Xray вынесены в `.github/xray.env`, оба workflow читают его первым шагом. Windows-раннер
  теперь распаковывает проверенный архив в `bin/`, поэтому и обычный `cargo test`, и шаг «Xray integration tests
  (must not be skipped)» идут с настоящим Xray.
- **D1.** Аудит просил «Engine и AppState хранят Lang». Язык уже хранится в `config.ui.language`, отдельного поля не
  заводил. `Engine::build` и `AppState::apply_view` привязывают текущий поток к этому языку (`i18n::bind_thread`),
  а `Setting::Language` дополнительно меняет язык процесса (`i18n::set`). Так юнит-тесты с разными языками остаются
  независимыми, а `cfg!(test)` пропал. Тесты берут `test_support::config_ru()`.
- **D2.** Типизированы `HealthError`, `FetchError`, `RuleError`; текст делает `Display` в момент показа (раньше
  в момент создания). Остальные тесты, которые сверяют русский статус, оставлены (см. ниже).
- **D3.** `RenderCtx { windows }` передаётся в `ui::render` и в экран правил. Варианты `_linux` и `_windows` сделаны
  только для экранов, где платформа что-то меняет (правила с пресетами). Дублировать все 78 снапшотов не стал: на
  остальных экранах варианты были бы одинаковыми. Тестовые конфиги фиксируют данные платформы
  (`CoreConfig::for_platform`, `TunConfig::for_platform`), иначе путь `xray.exe` попал бы в снапшоты на Windows.
- **D4.** `with_demo` теперь не только для тестов и принимает конфиг; запуск демо в программе по-прежнему идёт через
  фон (`ELF_GATE_DEMO` читает `build_info::demo_data`). Клавиша F12 и `Action::DebugPanic` остаются в таблице клавиш, но
  в release клавиша не привязана (`lookup` пропускает привязку без `DEBUG_PANIC_KEY`, `8f2a6ec`, `45fd0b7`).
- **D6.** Поиск Xray для `tests/` вынесен в `elf_gate::testing` с `#[doc(hidden)]`: `tests/` видит только публичное API,
  отдельный крейт ради одной функции не оправдан.

## Доработки после аудита

- **F3 (`af1fac9`).** Проверка токена процесса-сервера убрана: неповышенный клиент не обязан мочь открыть токен
  повышенного `elf-gated.exe`, а TUN на Windows запускает фон через UAC. Теперь демон создаёт канал первым
  экземпляром с дескриптором `O:<SID>D:P(A;;GA;;;<SID>)(A;;GA;;;SY)`, клиент читает владельца объекта канала
  (`GetSecurityInfo`) и сравнивает со своим SID. Имя с SID сохранено. Записано в `docs/decisions.md`, сценарии
  (обычный запуск, TUN через UAC, подмена вторым пользователем) в `docs/windows-checklist.md`. Проверено только
  компиляцией; главное, что надо увидеть на Windows: у повышенного демона владелец канала это учётная запись
  пользователя, а не группа «Администраторы».
- **S2 (`8865d89`).** `check-cache.json` пишется через `write_atomic` (0600, уникальное имя, fsync). При старте демона и
  интерфейса процесс ставит `umask 077` (логи, которые ротация создаёт позже, получают 0600), создаёт `logs/` с 0700 и
  ужесточает уже существующее под state и config (файлы 0600, каталоги 0700, ссылки не трогаются). Тесты на права;
  дополнительно проверено запуском настоящего `elf-gated`.
- **D1 (`a5cbba4`, `a91c25c`).** Задачи tokio на воркерах не имеют привязки потока, и их тексты шли на язык процесса.
  В демоне он случайно совпадал с конфигом, в `multi_thread` тестах нет. Добавлены `i18n::scoped` (task-local язык) и
  `Engine::spawn`, им заменены 10 мест, где задачи движка делают тексты для интерфейса. Порядок выбора языка: поток
  (`bind_thread`, `with_lang`), затем задача, затем процесс. Тест в `multi_thread` с украинским (не язык по умолчанию
  и не русский тестов); без обёртки он падает с английским текстом (проверено).
- **F1 (`019c7e5`).** Проверка прав до запуска уже была: `tun::preflight` (Linux: root или `cap_net_admin` через
  `getcap`, Windows: `is_elevated`) идёт до запуска ядра и показывает диалог. Добавлено утверждение в тесте, что при
  отказе нет ни задачи старта, ни ядра. Предел: на Linux без `getcap` результат «неизвестно», запуск не блокируется,
  ошибку ядра переводит в тот же диалог `looks_like_missing_privileges`.
- **D4 (`45fd0b7`).** F12 в release больше не привязана к действию; в бинарнике нет текста паники (проверено).
- **CI (`87620be`).** Все `uses:` закреплены по SHA с версией в комментарии; `dtolnay/rust-toolchain` получил
  `toolchain: stable`. Других `uses:` в workflow нет.

## Отложено

- **F10.** Функциональная проверка DNS и TUN (`elfgate_e2e.py` в `unshare -rn`, nightly): нужен дизайн запуска и
  раннер без root, по коду это мало, по трудозатратам много.
- **Разбиение `Engine`.** Не просили. После D1-D4 зависимостей от `cfg` в нём меньше, но `engine/mod.rs` всё ещё
  около 1500 строк.
- **Статусные строки из D2 (отложено).** Тесты логики всё ещё сверяют русский текст статусов в `engine/session.rs` (около 7 мест),
  `tun/mod.rs` (`tcp_reachable`, пояснения), `xray/process.rs`, `engine/server_opts.rs`, `engine/ping.rs`,
  `platform/linux/tun.rs`. Это строки статуса, а не ошибки с причиной; для них нужны ключи или варианты статуса.

## Новые проблемы, найденные по ходу

Порядок по убыванию пользы к риску.

1. **Кеш проверок и логи читаются всеми (дополнение к S2). Исправлено в `8865d89`.**
   - Где: `src/xray/checkcache.rs:174` (`fs::write` во временный файл `check-cache.json.tmp`, без прав, без fsync),
     логи в `src/daemon.rs:15` и `src/main.rs:18` (`tracing_appender`, права по umask).
   - Чем плохо: в кеше тексты отказов Xray, в логах имена серверов и хосты; любой локальный пользователь их
     прочитает. Фиксированное имя временного файла как в F6.
   - Как исправить: писать кеш через `storage::write_atomic`; каталог логов создавать заранее через
     `storage::create_private_dir`, а не оставлять это логгеру.
   - Риск: низкий. Без Windows: да.
2. **Тесты оставляют каталоги при панике.**
   - Где: `src/engine/mod.rs` (`elf-gate-lang-*`), `src/xray/checkcache.rs`, `src/xray/validate.rs`,
     `src/xray/process.rs`, `src/platform/linux/tun.rs` (`std::env::temp_dir().join(...)` и ручной `remove_dir_all`).
   - Чем плохо: при падении теста каталог остаётся; так оставались `elf-gate-fakex-*` и `elf-gate-cc4-*` после
     упавших прогонов. Это тот же T1, но остаток.
   - Как исправить: заменить на `test_support::TempDir`.
   - Риск: низкий. Без Windows: да.
3. **Язык процесса общий для всех тестов.**
   - Где: `Setting::Language` вызывает `i18n::set` (глобальный `AtomicU8`); тест `the_language_is_applied...` меняет
     его и возвращает `En`.
   - Чем плохо: тесты, которые читают язык без привязки потока и без `with_lang`, могут увидеть чужое значение.
     Сейчас таких нет, но защиты нет. Часть про задачи движка закрыта в `a5cbba4` (`Engine::spawn`).
   - Как исправить: вынести «язык процесса» в явный параметр, которым пользуется только демон, а `Engine` брать из
     конфига; либо поток-привязку наследовать в задачи.
   - Риск: средний. Без Windows: да.
4. **Критерий «ошибка конфига» хрупкий.**
   - Где: `validate::is_config_error` (`Failed to start` или `infra/conf`).
   - Чем плохо: если Xray поменяет формулировку, все настоящие отказы станут `Unavailable`, и сервер перестанет
     краситься как отклонённый. Тест с настоящим Xray (`plain_public...`) это поймает, но только при установленном Xray.
   - Как исправить: оставить; следить, что интеграционные тесты в CI идут с Xray (шаг «must not be skipped»).
   - Риск: низкий. Без Windows: да.
5. **Проверка данных Xray в двух местах.**
   - Где: `tun::preflight` (`GeodataMissing`, `is_file`) и `validate::environment_problems` (открытие файла).
   - Чем плохо: два критерия «файлы на месте» могут разойтись.
   - Как исправить: одна функция в `xray::process` рядом с `asset_dir`.
   - Риск: низкий. Без Windows: да.
6. **`create_private_dir` создаёт отсутствующие родительские каталоги с правами 0700.**
   - Где: `src/storage.rs`.
   - Чем плохо: если `~/.local/state` ещё нет, он станет закрытым; это безопасно, но неожиданно.
   - Как исправить: создавать родителей обычным `create_dir_all`, а 0700 ставить только последним звеньям.
   - Риск: низкий. Без Windows: да.
7. **`start_core` получает `core_cfg` и `config` одновременно.**
   - Где: `src/engine/session.rs` (`StartRequest`): `core_cfg` это копия `config.core`.
   - Чем плохо: два источника одной настройки; вызывающий может передать разные.
   - Как исправить: убрать `core_cfg`, брать `&config.core`.
   - Риск: низкий. Без Windows: да.
8. **`cfg(unix)` в зависимостях и тестах при `compile_error!` для не-Linux unix.**
   - Где: `Cargo.toml` (`[target.'cfg(unix)'.dependencies]`), `#[cfg(unix)]` в `storage.rs`, `xray/*`, `daemon_e2e.rs`.
   - Чем плохо: непоследовательно: сборка под macOS всё равно упадёт на `compile_error!`.
   - Как исправить: привести к `target_os = "linux"` при очередной правке этих мест.
   - Риск: низкий. Без Windows: да.
9. **Права доступа к токену повышенного процесса (F3). Заменено в `af1fac9`: проверяется владелец канала.**
   - Где: `src/platform/windows/ipc.rs` (раньше `served_by_same_user`).
   - Чем плохо: если Windows не даёт неповышенному процессу открыть токен повышенного `elf-gated.exe` (TUN через
     UAC), клиент откажется подключаться, и режим TUN на Windows перестанет работать.
   - Как исправить: проверить по чеклисту; запасной вариант проверять владельца самого объекта pipe
     (`GetSecurityInfo`) или имя образа процесса.
   - Риск: средний. Без Windows: нет.
10. **Снапшоты на Windows-раннере не проверялись.**
    - Где: `macro_rules! snap` в `src/ui/mod.rs`.
    - Чем плохо: сравнение включено везде; если на Windows что-то отличается (переводы строк в insta, пути), CI
      покраснеет. Данные тестов от платформы не зависят, но проверить можно только на раннере.
    - Как исправить: посмотреть первый прогон CI на Windows.
    - Риск: низкий. Без Windows: нет.
11. **YAML проверен упрощённым парсером.**
    - Где: `.github/workflows/*.yml`.
    - Чем плохо: `actionlint` и полноценного YAML-парсера в окружении нет; проверен только разбор модулем
      `CPAN::Meta::YAML` (структура, число шагов).
    - Как исправить: прогнать `actionlint` локально или на первом запуске CI.
    - Риск: низкий. Без Windows: да.
12. **Флейк `tcp_ping_measures_open_ports_and_reports_closed_ones`.**
    - Где: `src/net/ping.rs` (тест), один сбой в параллельном прогоне; три повторных одиночных запуска зелёные.
    - Чем плохо: «закрытый» порт берётся как `bind(0)` и сразу освобождается, его может занять соседний параллельный
      тест; тогда пинг вместо ошибки видит открытый порт (тот же TOCTOU, что у `free_ports`).
    - Как исправить: брать порт из диапазона тестовых портов `free_port()` из `integration_tests` или держать
      слушателя без `accept`.
    - Риск: низкий. Без Windows: да.
13. **`umask 077` наследуют дочерние процессы и новые файлы.**
    - Где: `platform::private_umask`, вызывается из `storage::prepare_private_files`.
    - Чем плохо: ядро Xray и `kwriteconfig` наследуют маску; файл `autostart/elf-gate.desktop` и другие файлы, которые
      создаёт сам elf-gate вне своих каталогов, получат 0600. Для пользователя это безвредно, но неожиданно.
    - Как исправить: если помешает, ставить маску только на время создания логов или сбрасывать её в `pre_exec`
      дочерних процессов.
    - Риск: низкий. Без Windows: да.
