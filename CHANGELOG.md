# Изменения

## 2.0.0

### Мышь

- Интерфейс управляется мышью: клик по панели переводит на неё фокус, клик по серверу выбирает его, второй клик
  (или двойной) подключает, как Enter. Стрелка заголовка подписки сворачивает и разворачивает её, двойной клик по
  заголовку открывает экран подписки.
- Колесо прокручивает тот список, на котором стоит курсор, а не тот, что в фокусе: в списках с выделением один
  щелчок двигает выделение на строку, в журнале и справке - на три строки. Пачка событий от одного щелчка не
  складывается.
- Кликабельны и строка статуса (режим PROXY/TUN переключается, «Доступна X.Y.Z» открывает окно обновления), и строки
  настроек, правил, экрана подписки и экрана проверки; флажок правила включает и выключает его.
- Клавиши в нижней строке стали «кепами» (клавиша на подложке, рядом подпись), каждая кликабельна и подсвечивается
  при наведении. Те же кепы-кнопки стоят в окнах вопросов, ввода, выбора, выбора процесса и в окне обновления: «добавить»
  или «сохранить», «отмена», «вставить».
- Окно закрывает собой всё, что под ним: клик и колесо мимо окна ничего не делают.
- Настройка «Мышь» (включена по умолчанию) в разделе «Внешний вид». Чтобы выделить текст в терминале, зажмите Shift.
  Если терминал не присылает события мыши, всё работает с клавиатуры.

### Правила без переподключения

- Включение и выключение правила или пресета больше не перезапускает ядро: новый список правил отправляется работающему
  Xray через его API, и открытые соединения не рвутся (раньше в режиме TUN рвались все, включая прямые). Порядок
  правил такой же, как при полном запуске.
- Перезапуск остаётся для того, что API изменить не может: смена сервера, режима include/exclude, DNS, портов, настроек
  TUN. В режиме TUN перезапуск нужен и пресетам со списками доменов (`games-direct`, `ru-direct`, `ua-direct`) и
  правилам по доменам: они меняют настройки DNS. Если ядро не приняло правила, оно перезапускается само, причина
  пишется в журнал.
- После применения программа напоминает, что уже открытые соединения идут прежним маршрутом, и когда стоит
  перезапустить программу.
- Linux: правила по процессам с длинными именами (`chrome_crashpad_handler`, `cowork-linux-helper`) работают: Xray
  сравнивает полное имя файла, а выбор процесса в программе показывает именно его.

### Безопасность

- API ядра (оно умеет менять маршрутизацию всей машины) закрыто от других программ. Linux: вход API - unix-сокет с
  правами 0600 в каталоге состояния. Windows: случайный порт на `127.0.0.1`, новый при каждом запуске ядра, а не
  фиксированный 10085.
- В настройках больше нет «Порта API». В `config.toml` вместо `api_port` ключ `api_enabled` (по умолчанию `true`);
  старый ключ читается один раз при загрузке и больше не пишется.

### Экран «Проверка» (клавиша `c`)

- Новый экран диагностики: ядро и его версия, данные geoip/geosite, доступность сервера по TCP и через URL, DNS
  (напрямую и через сервер), права TUN, Wintun, брандмауэр, адаптер от прошлого запуска, системный прокси, внешний
  адрес через VPN и прямой доступ к российским сайтам. У проблемы - строка «что делать», у части есть исправление по
  Enter (с вопросом).
- Отчёт копируется в буфер обмена (`y`): адреса и имена серверов заменены на «сервер N», ссылки, ключи и сайты из
  журнала скрыты. В отчёте версия, система (например, «CachyOS Linux (ядро 7.3.3)») и оба Xray - основной и для TUN.
- В режиме PROXY (и после отката TUN -> PROXY) экран предупреждает, что WebRTC в браузере может показать настоящий IP,
  и советует TUN или ограничение WebRTC в браузере (Chromium, Firefox). Та же фраза добавлена к сообщению об откате и
  к пояснению режима PROXY.
- На Linux в режиме TUN проверяется то ядро, которое реально используется (версия, права); если версия отличается от
  основной, подсказка предлагает обновить через `elf-gate-tun.sh`.
- Версия Xray показывается коротко («Xray 26.11.9»).

### Внешний вид и настройки

- Темы: Catppuccin Mocha и Latte, а также тема «terminal» (цвета вашего терминала); прозрачный фон; режимы 256 цветов,
  16 цветов и `NO_COLOR`. Подсвеченная строка читается на любой теме (контраст не ниже 4,5:1).
- Экран настроек разбит на разделы (внешний вид, подключение, подписки, TUN, пинг, ядро, обновления, порты,
  устройство), по ним переключают `Tab` и `[` `]`. Под таблицей - пояснение к выбранной строке на трёх языках.
  Строки, которых нет на вашей системе, скрыты.
- Экран подписки: имя, адрес, User-Agent, интервал обновления, HWID, скрытые серверы, обновление и удаление; значения по
  умолчанию задаются в настройках, у каждой подписки их можно переопределить и сбросить.
- Один компонент прокрутки для справки, настроек, подписки, правил и окон; выбор процесса с фильтром, имена отсортированы,
  одинаковые склеены. Окна на 80x24 не закрывают строку клавиш.
- Пинг по URL (через сервер) теперь по умолчанию; старый конфиг с `tcp` один раз переводится на `url`. Ручной пинг по
  URL без Xray предлагает переключиться на TCP.
- Ctrl+V в окне добавления вставляет ссылки или подписку из буфера обмена (на Windows через системный API, без PowerShell).
- Свёрнутые повторы в журнале склоняются правильно («ещё 1 раз / 2 раза / 5 раз», на украинском и английском тоже).
  Предупреждения Xray о закрытых соединениях (`proxy/http`, `proxy/socks`: «closed pipe», «unexpected EOF») в интерфейсе
  видны только на уровне `debug`, в файле журнала остаются.
- Везде обычный дефис вместо длинного и среднего тире.

### Сборка и выпуск

- Локальная сборка берёт короткий хэш коммита из git (`elf-gate --version`).
- Архивы стали меньше и строже: в них только программы, ядро, `geoip.dat`, `geosite.dat`, `wintun.dll` (Windows),
  `elf-gate-tun.sh` (Linux) и лицензии. Список файлов один на обе системы, сборка падает при лишнем или недостающем
  файле. Папка `locales/`, `presets.toml`, `bin/`, `README.md`, суммы внутри архива и `elf-gate-tun.bat` убраны.
- Linux-сборка идёт на Ubuntu 22.04: нужна glibc 2.35 или новее. Действия GitHub обновлены до версий на Node 24 и
  закреплены по хэшу коммита.

### Известные риски

- Часть нового проверена только автоматически: на Windows - буфер обмена через системный API, мышь в старом
  терминале (conhost) и в Windows Terminal, архив Windows (собирается на CI). На Windows порт API виден любому
  локальному процессу, пока работает ядро (Xray не умеет API на именованном канале), но он случайный и меняется
  при каждом запуске.
- Клик в поле ввода не ставит курсор внутри строки: у поля нет курсора, текст дописывается и стирается с конца.

## 1.0.3

Предварительный выпуск (pre-release).

### Смешанный режим TUN + PROXY

- В режиме TUN системный прокси теперь можно держать включённым одновременно с туннелем: в настройках появился
  переключатель, а в строке состояния режим показан как `TUN+PROXY`. Так приложения, которые ходят через системный
  прокси, и приложения, которые ходят напрямую, работают через один и тот же сервер.
- Если TUN не запустился (нет прав, не создался адаптер), программа сама переходит на системный прокси (PROXY), а не
  остаётся без соединения. В строке состояния видна пометка «TUN не запустился», причина записана в журнал.
- После включения TUN программа подсказывает, что уже открытые приложения продолжают идти старым маршрутом, пока их
  не перезапустить.

### Автозапуск с TUN

- Windows: автозапуск в режиме TUN теперь делается задачей планировщика заданий, которая запускается при входе в
  систему с правами администратора. Запрос UAC появляется один раз, при включении автозапуска, а не при каждом входе.
  Выключение автозапуска удаляет задачу. Если папку с программой перенесли, путь в задаче исправляется при запуске.
- Для режима PROXY автозапуск остаётся обычной записью в `Run` и прав администратора не требует.
- Если при автозапуске соединение не удалось (например, не хватило прав), вопрос или ошибку вы увидите, как только
  откроете интерфейс, а не потеряете их.

### Уведомление об обновлениях

- При запуске и раз в сутки (не чаще раза в 6 часов) программа смотрит список релизов на GitHub. Ничего не
  скачивается и не устанавливается: если вышла версия новее, в строке состояния появляется «Доступна X.Y.Z».
- Клавиша `n` открывает окно со списком изменений и ссылкой на страницу релиза. Клавиша `s` в этом окне: «больше не
  напоминать об этой версии» (о следующей версии напоминание вернётся).
- В настройках: «Проверять обновления» (включено по умолчанию) и «Канал обновлений»: стабильные (по умолчанию) или
  тестовые (с предварительными выпусками). Если напрямую GitHub недоступен, а VPN подключён, запрос повторяется через
  него. Ошибки проверки пишутся только в журнал.

### Выпуск

- Сборки для Linux и Windows теперь собираются и публикуются автоматически: архивы и файл `SHA256SUMS` попадают в
  черновик релиза.

### Известные риски

- Всё новое в этом выпуске проверено только на CI (автоматические тесты на Linux и Windows). На настоящей Windows
  (автозапуск задачей планировщика, смешанный режим, откат на PROXY) его ещё проверяют тестеры.
- Окно справки на очень низком терминале (около 24 строк) не помещается целиком: добавилась строка про клавишу `n`.

## 1.0.2

Предварительный выпуск (pre-release).

### Безопасность

- Файлы с настройками, подписками, кешем проверок, журналами и конфигом ядра теперь доступны только владельцу
  (права 0600, каталоги 0700 на Linux). Раньше их мог прочитать любой локальный пользователь, а в них лежат ссылки
  с UUID и токены подписок. Права старых файлов исправляются при запуске.
- Linux: при запуске через `sudo elf-gate` программа больше не меняет владельца файлов, на которые указывают
  символические ссылки в каталоге состояния.
- Запись настроек стала надёжнее: данные сбрасываются на диск до переименования, у временного файла уникальное имя,
  поэтому сбой питания не оставит пустой `config.toml`, а два процесса не портят друг другу запись.
- Windows: связь интерфейса с фоновым процессом идёт по именованному каналу, имя которого содержит SID пользователя
  (а не имя из переменной окружения). Канал создаётся с владельцем и правами только для вашей учётной записи и SYSTEM,
  а интерфейс перед работой проверяет, что канал принадлежит ему. Это закрывает подмену канала другим пользователем
  и работает при перезапуске фона с правами администратора для режима TUN.

### Windows: русская и украинская система

- Ошибки Xray, которые система выводит на своём языке («Отказано в доступе», «Не удается найти указанный файл»,
  украинские варианты), теперь распознаются. Раньше такая ошибка не превращалась в вопрос о перезапуске от
  администратора, а проблема окружения (недоступный `geoip.dat`) запоминалась как «сервер отклонён», и сервер
  оставался помеченным плохим, даже когда проблема уходила.
- Перед проверкой сервера программа сама смотрит, читаются ли `xray` и файлы `geoip.dat` и `geosite.dat`. Если что-то
  не так, вы видите эту причину, а вердикт о сервере не запоминается. Сбой проверки без ответа Xray о конфиге тоже
  не помечает сервер как отклонённый.
- Список сетевых адаптеров на Windows читается из выровненного буфера и не зацикливается.

### Windows: повторный запуск TUN

- Исправлен сбой, из-за которого в режиме TUN любой перезапуск ядра (смена правил, смена сервера, переподключение)
  падал с ошибкой `Cannot create a file when that file already exists` (0xC0000035 / 0xB7). Работало только первое
  подключение после перезагрузки Windows.
- Ядро теперь останавливается мягко (сигнал Ctrl+Break, до 5 секунд) и успевает удалить свой адаптер, а не убивается
  сразу.
- Перед запуском программа ждёт, пока старый адаптер исчезнет, и удаляет оставшийся (в том числе «призрачный») адаптер
  только с именем `elfgate0`; чужие адаптеры не затрагиваются.
- Если такая ошибка всё же возникла, программа один раз чистит и повторяет запуск, а затем показывает понятный совет
  (перезагрузить компьютер и пока использовать режим PROXY) с логом Xray под ним. Ошибка распознаётся на английской,
  русской и украинской Windows.

### Windows: локальная блокировка соединения (10013)

- Ошибка `os error 10013` (WSAEACCES) означает, что соединение запретила сама система: брандмауэр, антивирус или
  сетевой фильтр другого VPN (ExitLag и т.п.). Раньше она выглядела как «Сервер недоступен по TCP». Теперь вы видите
  «Windows запретила elf-gate подключиться к <адрес> - проверьте брандмауэр, антивирус и другие VPN-программы»
  (на английском, русском и украинском). Сервер при этом не помечается недоступным, пинг остаётся «-», вердикт
  не запоминается.

### Windows: брандмауэр

- С правами администратора (режим TUN) при запуске фоновый процесс сам создаёт в брандмауэре Windows разрешающие
  правила `elf-gate` (входящие и исходящие, все профили) для `elf-gate.exe`, `elf-gated.exe` и `xray.exe`. Если
  папку с программой перенесли, путь в этих правилах обновляется. Используется COM API брандмауэра, а не `netsh`,
  поэтому язык системы не важен.
- Блокирующие правила, которые Windows создала для этих программ после «Отмена» в окне брандмауэра, удаляются;
  каждое удаление пишется в журнал. Чужие правила не затрагиваются.
- Без прав администратора (режим PROXY) правила не меняются. Ошибки брандмауэра не мешают подключению и попадают
  только в журнал.
- При ошибке 10013 программа предлагает «Настроить брандмауэр»: `elf-gated.exe` запускается с запросом UAC только
  для этой операции и сразу завершается.
- Новая настройка «Настраивать брандмауэр Windows автоматически» (по умолчанию включена).

### Прочее

- Проверка прав для режима TUN идёт до запуска ядра и подтверждена тестом: без прав Xray не запускается, вы видите
  понятное сообщение.
- Параллельный запуск нескольких проверок порта для URL-пинга повторяет попытку, если порт заняли между выбором и
  запуском.
- Клавиша F12 (аварийная остановка для разработчиков) убрана из релизных сборок.
- Язык интерфейса теперь передаётся явно во все фоновые задачи: тексты ошибок и статусов всегда на выбранном языке.
- Сборка поддерживает только Linux и Windows; остальные unix-системы раньше собирались, но не работали.
